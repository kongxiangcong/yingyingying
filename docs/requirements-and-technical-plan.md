# 英语情境表达练习：需求与技术方案

日期：2026-10-25  
状态：需求与总体方案已确认；尚未开始实现。文中的接口、数据结构和实施步骤为实现建议，不代表已验证能力。

## 1. 产品定位

用美剧、动画等真实剧情练习英语表达：用户先理解上下文，在角色开口前尝试组织台词，然后听原句、对照表达、提炼可复用的句式。

目标用户已有一定英语知识，但缺乏把已有知识组织成自然表达的能力。长期目标是在情境中独立说出合适的话；第一阶段明确采用“原句重构练习”：结合剧情、中文与逐词空位还原演员原句，反复练习表达模式（pattern），不承担自由表达测评。

核心不是“听完再听写”。目标句在作答前不能被播放或通过字幕提前展示。原句匹配只用于学习对照，不代表其他表达不成立。

工作假设：情境中的尝试、原句反馈和句式总结有助于积累表达能力。实际迁移效果仍需通过使用验证，不能直接宣称练过原句就能自由表达。

## 2. 第一版范围

### 已确认保留

- 本地完整视频与配套英文字幕导入。
- 简单素材库：查看素材、预处理状态、进入学习、保存学习位置。
- Python 脚本经模型 API／harness 提前完成学习资料规划。
- 在目标句开口前自动暂停，展示中文与逐词填空。
- 每题独立的四档提示。
- 作答实时反馈，答对后自动收起蒙版、播放原句并显示英文字幕，连续播放后续剧情。
- 视频播完或用户主动结束本次学习时生成学习报告，集中梳理原句、表达模式和作答情况。
- 记录各暂停点的完成情况与提示使用程度，将卡顿题收录到错题本。
- 第一版提供独立的错题本入口，用户自行决定何时复习；复习直接显示中文与英文填空，不播放视频，不安排到期时间或复习频率。
- 暂停、继续、原句重播等播放控制。
- 完整视频配练习时间表，不以切割视频文件为默认方案。

### 推迟

- AI 评分、语义纠错、判断多种等价答案：避免等待和复杂判分打断练习。按原句进行确定性实时匹配属于已确认范围。
- 口语录音、发音评分、自由对话。
- 流媒体接入、线上素材抓取、云端视频库。
- 用户账号、多设备同步、桌面安装包。
- 复杂分类搜索、社交、打卡、记忆曲线调度与自动复习提醒。第一版仅提供用户主动使用的错题本练习。
- 无独立字幕素材的自动转写、画面字幕 OCR、视频视觉理解。

这些功能不妨碍验证核心流程，待本地学习闭环稳定且出现明确需求后再考虑。

## 3. 学习流程

1. 用户从已完成预处理的素材中开始或恢复学习。
2. 连续播放剧情，默认显示英文字幕、不显示中文字幕，让用户建立上下文。
3. 到预先规划的暂停点，在目标句声音出现前暂停。
4. 保留暂停的视频画面，在播放器区域覆盖浅灰半透明蒙版，使背景变淡、变灰；正中央弹出目标句的中文表达与英文空位，每个空对应一个预先确定的单词单位。
5. 用户填写，可以逐级请求提示，也可以随时直接揭晓。
6. 作答过程中实时反馈是否匹配原句；答对后自动收起做题蒙版，正常播放原句并显示英文字幕。
7. 原句结束后自动继续剧情，不再逐题暂停展示句式卡，不要求用户点击“继续”；进入下一题时提示等级重置为默认难度。
8. 以一份视频为一个学习单元，视频播完自动生成学习报告，也允许主动“结束本次学习”。报告区分已完成、揭晓与未做题，汇总原句、句式卡、卡顿情况及错题内容；由预生成资料和实际作答记录直接汇总，不等待模型。未做题仅显示数量和位置，隐藏原句与句式卡，避免恢复学习时泄露答案；已完成或已揭晓题正常展示。

实现约束：

- 当前目标句作答前隐藏对应英文字幕；字幕列表、预览等也不得提前泄露答案。
- 原句揭晓不要求用户必须逐词答对，也不使用 AI 判分阻挡继续。
- Pro Max 与独立的“直接揭晓”按钮均属于用户主动请求揭晓：展示并填入完整答案，进入原句播放流程，不计作独立完成。“直接揭晓”无需先使用其他提示，按 Pro Max 计入复习。
- 提示增加时保留已填写内容；与揭示词冲突时展示原词，并保留用户原始作答用于对照。
- 向前拖动不补弹沿途题目，也不将这些题目标为完成；向后回看时已完成题目不再自动弹出，可主动重做，未完成题目正常播放到暂停点时仍触发。
- 退出后恢复原来的学习状态：作答中的输入及提示等级保留，剧情恢复到原播放位置且先保持暂停，由用户主动启动播放。旧的逐题句式卡恢复场景已随流程调整取消；报告页面恢复细节待确认。
- 练习界面的播放与总结读取预生成数据，不调用模型。

### 实时匹配

按每个单词空位即时反馈，输入完全匹配时立即标绿，整句全部匹配后自动通过。匹配忽略大小写、首尾空格及弯直撇号差异；句末标点预先显示，拼写必须符合原句，不接受同义改写。尚未输入完成的词保持中性，避免逐字母报错；按空格、Tab、Enter 或切换输入框时才检查不匹配并记录一次错误，最后一个词匹配后整题自动通过。

### 作答界面视觉约定

参考用户于 2026-10-25 上传的界面图片：中文题意使用醒目的大字，下方排列逐词下划线输入位，长句允许换行，当前输入位用颜色强调。题目整体位于播放器正中央，不放在底部字幕区；背景视频通过浅灰半透明蒙版弱化，题目文字与输入控件保持清晰、不随背景一起变透明。图片用于布局参考，其中的示例内容及其他界面元素不自动成为功能要求。

作答前中央显示的是中文题意和英文空位，不显示完整英文答案；目标英文字幕在底部字幕区和其他入口同样隐藏。蒙版只负责视觉呈现，不能替代答案隐藏逻辑。

## 4. 每题四档提示

以 `How are you today?` 为交互说明；该句不代表默认应被选为练习。

| 档位 | 显示与行为 |
|---|---|
| 默认难 | `_ _ _ _`，所有词由用户填写 |
| Tips | 例如 `_ _ you _`，揭示预先选定的部分单词 |
| Tips Pro | 保持部分揭词，并给出剩余词的打乱候选，例如 `today、How、are` |
| Tips Pro Max | 显示完整原句并自动填好 |

- 提示只能逐级增加，不是全局难度设置；独立的“直接揭晓”按钮允许随时跳到完整答案。
- 下一题重新从默认难开始。
- 候选词应保留重复词的数量；第一版无需引入干扰词。
- 句末标点不作为空位，直接显示。缩写与连字符词各占一个空，例如 `didn’t`、`well-known`；内部撇号与连字符属于单词。由程序统一生成并校验，不能在不同提示档位改变空位数量。
- 提示揭示位置应提前规划；程序确认索引有效、内容与原句一致。

## 5. 选句与句式总结

### 选句原则

选择能复用的自然表达、固定搭配、句式与交际功能，例如解释误会、提出请求、表达拒绝或说明原因。结合前后台词理解含义，不能只对孤立的一句生成题目。

默认跳过简单语气词、普通寒暄，以及必须依赖画面动作才能可靠解释的台词。优先选择文字上下文足够明确、时间边界清楚、适合练习长度的句子。保留剧情连续性，不逐句打断。

第一轮可用约 5 分钟素材、3–5 道题验证体验；这是实验起点，不是固定出题密度。具体密度、句长及等级阈值待试用后确定。

### 学习报告中的句式卡

句式卡在结束后的学习报告中集中展示，不再逐题自动弹出；默认简短展示，详细语法解释按需展开：

| 内容 | 示例 |
|---|---|
| 原句 | I didn’t realize you were serious. |
| 情境用途 | 发现自己先前误解了对方：我之前没意识到你是认真的。 |
| 表达骨架 | I didn’t realize + 一件之前没意识到的事 |
| 结构说明 | realize 后接完整信息，这里省略连接词 that。 |
| 迁移例句 | I didn’t realize you needed help. 我之前没意识到你需要帮助。 |

重点是“什么情况下可以这样说、哪些内容可以替换”，而不是仅标注语法术语。不强行把每句话归为句型；学习点也可以是固定搭配。总结与题目一起预生成。

### 暂停点记录与复习

分别保存完成状态与本次作答使用的最高提示等级，展示为未完成、无提示通过、Tips 通过、Tips Pro 通过、Pro Max 揭晓。“直接通过”统一称为“无提示通过”，与“直接揭晓”区分。使用过提示但尚未答完仍是未完成，并保留提示等级。

反复输错但最终不用提示答对，仍记为无提示通过，同时保留错误次数；错误计数按实时匹配章节约定。独立的“直接揭晓”按 Pro Max 收录到错题本。

Tips、Tips Pro、Pro Max 三类卡顿题收录到错题本；不再按记忆曲线计算间隔，不安排到期时间或复习频率。用户自行决定何时进入错题本复习，不插入正在观看的新剧情。复习从无提示开始，直接显示中文题意与英文空位，全程不播放视频，沿用实时匹配与提示机制。

错题保留历史，不因一次答对自动删除或自动标记掌握。用户可手动标记“已掌握”；默认练习未掌握题，已掌握题仍可查看并重新加入练习。

复习中，无提示答对、使用提示后答对、Pro Max 或直接揭晓均统一停留在当前题，按 Enter 进入下一题，不自动切题。尚未完成时 Enter 仅按输入规则检查当前单词，不能跳题；使题目进入完成状态的同一次按键不能同时触发下一题，需新的 Enter 按键。此规则仅用于错题复习，视频学习仍按既定规则自动播放原句并继续剧情。

## 6. 素材约定

| 素材 | 第一版约定 |
|---|---|
| 视频 | 优先 MP4 容器，H.264 视频编码、AAC 音频编码；导入时检查实际编码，不只检查后缀 |
| 英文字幕 | 独立 SRT 或 VTT，UTF-8 编码，包含起止时间 |
| 中文字幕 | 不强制要求，由 AI 结合上下文提前生成 |
| 只有内嵌画面字幕 | 暂不作为受支持的唯一字幕来源 |

字幕必须与视频版本匹配。导入需检查文件可读性、字幕时间格式、时间范围和编码；不支持的文件应明确说明原因。自动转码的范围待实现时确定，不能默认承诺所有 MP4 均可直接播放。

一条字幕不等于一句台词：一句话可能跨多条字幕，一条字幕也可能包含多个说话人的对白。预处理应形成适合练习的台词单位，并保留其来源字幕标识。

## 7. 完整视频与练习时间表

原始视频保持完整。每道题记录目标文本、来源字幕、暂停点、原句开始与结束时间。播放器依据时间表控制播放，不必生成大量短视频文件。

例如（仅示意，不是固定偏移策略）：

```text
暂停点       02:14.100
原句开始     02:14.400
原句结束     02:17.200
目标台词     I didn’t realize you were serious.
```

字幕时间只能作为初始依据，不能保证等于真实发声边界。暂停点既要避免泄露目标句，也不能随意截断上一句。用户不接受逐题人工确认或人工修正作为学习前置流程；允许自动跳过边界不可靠、不适合安全暂停的台词，减少出题数量。整份素材无法生成可用题目时，明确提示更换素材，不要求用户人工修正。不得让语言模型猜测精确时间；识别不可靠边界的自动方法仍需实现和验证。

第一版优先选择视频与英文字幕匹配、适合练习的素材，不设置用户人工核准题目的流程。后续由助手协助寻找学习素材视频，小猪佩奇是用户提出的候选。素材适配性与播放器暂停准确性仍需分别验证；必要时是否引入音频对齐尚待讨论。

播放器不可仅依赖普通 `timeupdate` 事件保证准确暂停；实现时需选择合适的时间检查方式，并在真实视频、跳转及重复播放场景中验证。若仍有声音泄露，需要进一步调整播放方案。

## 8. 技术架构

运行形态：本机服务，浏览器访问界面。本地保存视频、字幕、练习包与学习记录；预处理将需要的字幕文本发送给所配置的模型服务。第一版不需要上传完整视频给语言模型。

| 层 | 方案 | 职责 |
|---|---|---|
| 前端 | React + TypeScript + Vite | 素材库、播放器、填空、提示、句式卡 |
| 本地后端 | Python + FastAPI | 素材登记、任务状态、媒体读取、练习包与进度接口 |
| 预处理 | 独立 Python 工作进程 | 字幕解析、调用 harness、校验、生成练习包 |
| 存储 | SQLite + 本地文件 | 元数据、任务和学习进度入库；素材及练习包保存文件 |
| 媒体工具 | FFmpeg／ffprobe | 检查媒体、按需提取音频或转码 |
| 可选对齐 | 后续按实际需要选择 | 校准字幕与真实声音边界 |

媒体服务需支持浏览器按区间读取和跳转。预处理独立于交互服务，避免任务耗时影响学习页面。第一版无需部署 Redis、Celery 等分布式任务设施。

## 9. Python 与 Codex／DeepSeek harness 预处理

沿用用户在 FOCUS／ArcHa 中采用的“Python 编排、模型预处理、结果落盘后使用”的工作方式。本轮未审查这两个项目的当前代码，不能假设它们的 harness 可直接搬用。

模型调用层与业务流程分离：Python 脚本通过统一适配接口调用 Codex 或 DeepSeek harness。具体 Codex 接入是 SDK、CLI harness 还是直接 API，以及 DeepSeek 的接口与配置，实施前检查已有可复用代码后确定；不假设两者参数或返回协议完全相同。模型供应商、模型名、超时和重试策略由配置选择。

### 建议流水线

1. **登记与检查**：登记本地视频和字幕，生成素材标识，检查时长、编码与字幕时间范围。
2. **解析字幕**：规范文本，保留来源时间与标识，合并／拆分适合练习的台词单位。
3. **准备上下文**：向模型提供有序台词及必要上下文；较长素材按上下文窗口分块并处理重叠，避免丢失情境或重复出题。
4. **筛选表达**：模型返回来源标识、入选理由和学习点；原始英文以字幕为准，不允许模型无声改写成另一句。
5. **生成资料**：输出中文、部分揭词建议、情境用途、表达骨架、解释和迁移例句。
6. **确定性组装**：程序生成或校验 tokens、空位、候选词与索引，把入选台词映射到原字幕时间。模型不负责凭空生成音频时间。
7. **校验与修正**：检查结构完整性、原文一致性、时间合法性、重复题、提示一致性；对不合格结果有限重试或标记待修正。
8. **发布练习包**：完成校验后一次性发布可读取的版本，保留来源与生成配置，页面仅加载已完成的版本。

任务应记录阶段、失败原因和已有产物，支持失败后重试，尽量复用已完成的结果。生成中或失败的半成品不得当作完整学习资料展示。

凭据通过环境变量或本地配置传入，不写入练习包、日志或代码仓库。本阶段只设计接口，不新增或调用模型凭据。

## 10. 练习包数据建议

采用版本化 JSON 保存预处理结果，SQLite 记录其位置、版本和状态。字段命名可在实现时调整，但应覆盖以下信息：

| 对象 | 需要保存的信息 |
|---|---|
| 素材 | 素材 ID、本地视频／字幕引用、时长、文件指纹 |
| 生成元信息 | schema 版本、源字幕指纹、模型／harness 标识、提示模板版本、生成时间 |
| 题目来源 | 题目 ID、来源字幕 ID、原始英文、中文、选句理由 |
| 播放计划 | 暂停点、原句开始／结束时间、时间校验状态 |
| 填空与提示 | tokens、标点、揭示词索引、候选词（保留重复词数量） |
| 句式卡 | 情境用途、表达骨架或搭配、结构说明、迁移例句及译文 |
| 学习记录 | 练习包版本、当前题目、播放位置、原始输入、最高提示等级、完成状态、错误次数、每次作答记录 |
| 错题与复习记录 | 关联题目与练习包版本、收录时提示等级、历次复习结果、用户标记的掌握状态；不保存复习间隔或到期时间 |
| 学习报告 | 本次学习范围与结束原因、已完成／揭晓／未做题、句式卡与卡顿及待复习汇总 |

建议统一使用相对视频起点的整数毫秒表示时间。学习记录独立于练习包保存。同一视频重新生成题目时，旧学习记录与错题保留，并继续关联原练习包版本和原题目；新练习包独立开始，不自动覆盖、迁移或合并旧记录。被学习记录或错题引用的旧练习包资料必须保留，确保旧题目仍可查看与复习。

## 11. 实施顺序与验收

### 阶段一：最小播放闭环

使用一个本地视频、配套字幕和少量固定题目，跑通素材列表、自动暂停、四档提示、实时反馈、答对后原句播放与自动继续，以及结束后的报告。此阶段可以使用固定练习包，不依赖模型调用，不要求用户逐题人工核准。用户不要求将学习意愿或迁移效果试用评估作为项目启动前置条件；功能验收仍按下列条件执行。

### 阶段二：接入预处理

加入 Python 流水线与一种已确认的 harness，生成相同结构的练习包；实现任务状态、结果校验、错误信息与重试。随后验证另一种适配器，而不是同时扩展所有调用方式。

### 阶段三：真实素材校验

检查多条字幕组成一句台词、多个说话人、缩写和重复词、字幕时间偏移、重播及恢复学习等实际情况。必要时增加时间修正或音频对齐能力。

### 阶段四：错题本练习（第一版内）

加入独立的错题本入口，由用户主动开始中文填空复习，不播放视频；核对题目收录、无提示重新作答、历史记录保留及报告中的错题汇总。

### 第一版验收条件

- 支持约定的本地视频和字幕，能看到预处理状态，处理失败有明确原因。
- 选中的练习在真实播放中不提前泄露目标句声音和英文字幕。
- 剧情播放默认显示英文字幕；作答时背景视频暂停并覆盖浅灰半透明蒙版，中文题意与逐词填空在播放器正中央清晰显示。
- 不可靠台词可自动跳过；没有可用题目时提示更换素材，不进入用户逐题核准流程。
- 题目按时间顺序触发，暂停、重播、继续和恢复不会导致循环出题。
- 每题四档提示准确递进，候选词与空位一致，下一题重置。
- 作答实时反馈，答对后自动收起蒙版、播放原句及后续剧情，无需逐题点击继续；揭晓也可进入原句播放流程。
- 视频播完或用户主动结束本次学习时生成报告，区分已完成、揭晓和未做题，集中展示原句、句式卡、卡顿情况及待复习内容，不调用模型。
- 报告中未做题只显示数量和位置，不泄露原句或句式卡；重新生成练习包后旧记录、旧题目与错题保持可访问，新版本独立开始。
- 错题本独立于新剧情，由用户自行决定何时复习；直接中文填空，不播放视频，不自动安排时间或频率。
- 错题答对不自动移除，支持手动标记已掌握及重新加入；复习答对或揭晓后统一按新的 Enter 按键进入下一题，不因同一次按键跳过结果。
- 任意提示等级均可直接揭晓，无需逐级点击提示。
- 学习过程不发起模型请求，不等待 AI 打分。
- 原视频无需物理分割，练习时间表能独立定位原句。
- 能保存并恢复学习位置；未完成的生成结果不会进入可学习列表。
