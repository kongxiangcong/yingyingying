# 10 声音边界：已实现与待验证的区别

日期：2026-10-25。用户随后明确允许本地对齐验证；已执行缓存 tiny.en 的断网 CPU 识别和真实浏览器验证。下文保留固定响应测试与真实入口证据的区别。

## 为什么需要独立声音对应

`timing-investigation.md` 已说明：台词前与台词内部都有静音。字幕偏移后，仅找最近静音会把首词后的空隙误认成开口前。全局字幕偏移估计同样不能证明具体词与音频的对应。因此取消原先“字幕间隔 >=600ms、字幕前400ms暂停”的发布依据。

现在独立本地声音边界只收到本机解码 WAV 路径、哈希与时长，不收到目标字幕作为识别 prompt。程序要求逐词完整原句准确对应且唯一，低置信、缺词、重复匹配、词时间重叠、显式多说话人或已标注音频重叠会跳过。程序再用实际 -42dB 静音区检查前句尾部与目标首词之间的空间：前句后留余量、首词前使用至少250ms时间戳预算与额外150ms余量、暂停位于静音内部。无安全题就提示更换素材；不发布空包，不交给用户逐题修时间。

没有显式配置独立声音入口时直接拒绝生成。固定练习包及已经发布的版本继续可用。

## 真实 Peppa 媒体，固定对齐响应

外部资料生成与声音对齐均使用明确标记的固定测试响应；对齐 fixture 的时间来自既有一次性核对结果，仅作为本轮测试输入，运行时不会读取这个历史文件。包 provenance 标记 `alignment_fixture_only=true`。目标为来源字幕27的 `Have you just had a bath?`；暂停点不是既有开发候选，程序从完整实际音轨解码和独立词序列自动计算：

- 前词结束：198140ms（固定响应）。
- 实际音轨静音：198274–199486ms（本轮 FFmpeg 16kHz 单声道 -42dB 检测）。
- 首词时间：199540ms（固定响应）。
- 自动暂停：198825ms，位于真实静音区内。

浏览器 AudioWorklet 在真实音频渲染线程采集输出；相对源 MP4 解码的实际首词语音 PCM 做归一化波形相关，不以暂停 DOM 或模拟时钟代替声音。观测支路输出静音、不替换原音频通路；消息缓冲跨主线程阻塞仍保留数据。一次通过结果：

| 场景 | 与目标首词源波形的最大相关 |
|---|---:|
| 作答前 | 0.1073 |
| 答对/揭晓后 | 0.9594 |
| 主动重播 | 0.9368 |
| 恢复作答后揭晓 | 0.99996 |
| 近暂停点前跳、主线程阻塞1100ms | 0 |

前一句声音与其源波形相关为0.9944，证明前文实际播放而不是从头静音。预先设定目标未出现阈值 <0.35，真实播放阈值 >0.6。恢复蒙版时视频暂停、采集目标为空；完成后目标真实输出。阻塞场景中增益截止在音频线程执行，主线程恢复后播放器回到安全暂停画面，不把解码/调度延迟归咎于素材。

## 其他边界夹具

- 已有独立预处理到学习的2项测试通过（19.1秒），声音时间现在由固定独立对齐与真实静音共同产生。
- 700ms 整体偏移的字幕与跨字幕句子仍映射到实际2200ms语音，不按字幕2900ms当首词；多说话人标记跳过。
- 未配置入口、低可信词及实际紧接声音夹具均拒绝发布，提示没有可用题目；当时4项应用级测试通过（34.4秒）。另补充已标记重叠/多说话人输出拒绝场景。

播放器在 `playing` 后重设截止点、`waiting` 时静音，并按自然播放逐帧重新同步音频截止点；暂停、跳转和恢复沿用05的独立保存与保护。

## 可执行真实入口与限制

`local-alignment-plan.md` 与 `scripts/align_local.py` 提供具体本机 faster-whisper / 缓存 tiny.en 命令，CPU int8、4线程、断网、禁止下载。已在用户明确授权后执行本轮真实本机推理，未调用外部LLM/API、未创建凭据、未下载模型。模型概率和250ms预算不是统计校准的绝对保证，这个轻量入口也不分离说话人。未标记的说话人变化、严重识别错词、设备/后台播放行为仍需按实际入口与媒体证据判断。

固定响应证明确定性边界行为；下面的真实入口验证进一步覆盖已授权本机环境和 Peppa 样本。两类证据互不替代，不把有限样本推为所有声音素材的保证。


## 与09合并后的验证

已保留09的任务租约、原子发布、有效缓存重验与进程树回收。独立声音命令使用 OwnedProcess 管理，超时回收所属进程树；声音身份（策略、命令哈希、脚本/模型/库元数据身份）进入新 pipeline-v3 指纹。没有入口时在模型调用前失败。校验始终重新计算，不复用旧字幕候选时间。

合并后生产构建通过，预处理/故障矩阵/真实服务重启/重试/6类声音场景/Peppa波形的12项浏览器测试通过（2.7分钟）。此外，布尔型伪概率不能当作1.0置信度，专门拒绝用例通过（14.3秒）。此前Peppa+03/05音频+声音边界9项回归通过（1.4分钟）。

偏移字幕额外红测试发现：揭晓后按原字幕显示会使整句过晚或只显示跨字幕片段。现在所有目标来源字幕由题目校验时间表接管，揭晓后在实际原句区间显示完整原句；目标区间浏览器复验通过（15.6秒）。


## 已授权的真实本地识别与声音验收

用户明确回复“允许本地对齐验证”后，实际调用 scripts/align_local.py，读取本轮解码的完整约310秒 Peppa WAV。资料生成仍使用固定测试回答，不调用真实 Codex/DeepSeek/OpenAI API。缓存 tiny.en 在 CPU int8 / 4线程下运行20.052秒，合计CPU72.312秒，输出313词。目标六词完整准确对应，最低词概率0.871889，超过事先设定的0.85；没有为通过测试降低阈值。

实际模型自动得到首词199540ms、前词结束198140ms，结合本轮实际静音198274–199486ms选择暂停198825ms。包标记 alignment_fixture_only=false，来源与完整选中词概率见 ticket10-real-alignment.json。源语音相关结果：作答前0.1073、前句0.9944、揭晓后0.9139、重播0.999998、恢复揭晓0.999965、1100ms主线程阻塞后0。实际入口完整浏览器验收通过（54.0秒）。

验证中发现并修正两项实际问题：缓存 PyAV19 与 faster-whisper 的文件解码调用不兼容，改为使用已经本机解码的16kHz PCM数组，不新增安装；用户在主动重做的内部跳转尚未完成时再拖动位置，会被误当作恢复跳转，现按具体恢复目标区分用户新跳转。修正后真实模型和全部声音场景共同通过。

重现真实入口：设置 SCENE_TEST_REAL_ALIGNMENT=1、SCENE_PYTHON 为项目隔离Python，再运行 npx.cmd playwright test tests/peppa-timing.spec.ts。默认测试仍使用固定声音响应，不会在普通回归中静默运行识别器。
