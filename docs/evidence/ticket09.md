# 09 预处理故障、重试与真实服务重启验收

日期：2026-10-25。边界：真实浏览器、React、FastAPI、SQLite、媒体与独立 worker；仅外部模型响应命令替换为固定脚本。没有修改应用内部状态或直接读写数据库来制造测试结果。

## 红绿与故障矩阵

`tests/retry.spec.ts` 的首次红测试在失败任务缺少 `model_attempts` 处失败，随后要求可见的“重试预处理”入口。实现后预处理/重试三项子集通过（30.1 秒）。

`tests/preprocessing-faults.spec.ts` 依次注入外部超时、非零退出、非法 JSON、非法结构、原文改写、重复题、越界揭词、词数不符、词单元不符、候选多重集合不符和缺失句式卡。所有错误均有阶段与原因；最多两次模型尝试后失败。每次失败保留同一旧版本，浏览器仍可进入旧包做题。

最后的无效句式卡响应不进入可复用缓存。修复外部响应后从界面重试，只复用两块有效选句产物，重新生成一次即发布；同一失败任务重复请求重试返回原有后继任务，不新增版本。该矩阵通过（54.3 秒；最终组合复验见末尾）。

## 中断与真正重启

`tests/preprocessing-restart.spec.ts` 启动自己持有的 API/Vite 子进程和临时持久目录，并通过浏览器导入素材与生成旧包：

1. 外部响应程序终止真正的预处理 worker，公开任务查询检测到进程创建身份已不存在，将任务标为中断。旧包仍存在，界面重试复用选句并成功。
2. 在下一轮模型调用期间，测试终止自己持有的真实 API 进程，再启动同一服务与数据库。Windows Job Object 回收其所属 worker/模型子树，重启后显示明确的中断状态，而非永久“处理中”。
3. 将实际运行配置改为另一模型名再重试；缓存指纹不同，不复用旧选句，完整重新请求并成功。
4. 再次真正重启服务，任务成功状态、三个版本与原始旧包仍可读取。重复重试请求不重复发布，浏览器可以继续学习。

此测试通过（34.2 秒）。外部故障脚本显式处理 Windows venv 的 launcher 进程，因此崩溃验证终止的是 worker，而非仅终止模型的 Python 包装器。

## 实现保障与限制

- 缓存指纹含视频 SHA-256、原字幕、供应商/模型、配置、提示/流水线版本及模型入口脚本哈希。资料完整校验后才缓存，读取缓存再校验；缓存文件使用临时写入再替换。
- worker 的执行租约撤销后不能继续写状态或发布；心跳与 PID 创建时间共同识别身份。清理使用保留的所属进程/Job 句柄，不盲目按 PID 终止其他进程。
- 包文件完整写入后，版本索引与任务成功在同一 SQLite 事务提交；未索引文件不对学习接口可见。任务与其重试后继具有唯一约束。
- Windows Job 辅助实现参考并复用了本机已检查的 ArcHa `opc/core/windows.py`。本次验证平台为 Windows / CPython 3.14；不据此宣称其他操作系统的进程回收已实测。
- 媒体可靠暂停、独立音频边界认证仍由 10 提供；本工单不把字幕间隙当作真实对齐证据。
- 固定响应只证明应用集成与恢复行为；真实模型认证、服务与输出质量未调用、未验证。
